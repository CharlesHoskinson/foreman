# 2026-07-29 — S1 implemented, four stages opened, nothing merged until now

Written from the day's commits and audit reports, not from memory. Twenty-two
commits on `main`, nine feature branches, twelve audits — **every one BLOCKED,
none a false alarm.**

---

## 1. What actually happened, in order

Started by recovering the previous session's work, which had been committed
locally and never pushed. Nine commits went to GitHub, and a **second divergent
checkout** on the Windows side turned out to hold sixteen `bugeventlog.md`
entries and a `pwd -P` fix that existed nowhere else. Both recovered.

Then S1. `crlf-extensionless-hardening` took **six rounds**, and the reason is
the single most instructive thing in the day: **the same defect relocated five
times.** A hardcoded SDD list → a `*.sh` extension filter on the foreman tree →
the repo root reached by no pathspec → the repo root as a literal singleton → a
region not in the list at all. Every fix repaired the instance it was shown.
The class only closed when the predicate was **inverted** — sweep the whole
repository by index-blob shebang and enumerate *exclusions*, each carrying its
reason. An inclusion list can always be relocated out of; an exclusion list
covers files that do not exist yet.

`lock-primitive-hardening` took **seven rounds across four sub-packages**. L1
(the helper) was audited BLOCKED with five HIGH, reworked, then re-audited: all
six original findings fixed and **three new ones introduced by the fixing** —
a caller-owned FD 3 destroyed on the success path, a trap that overwrote the
caller's own traps in both directions, and idempotent init that trusted
inherited environment. L2 (the trust plane) shipped its pinned register
**deliberately empty**, with the reason in the file: no Foreman-controlled
Git-Bash host existed to capture a syscall trace, and *"a fabricated entry is
worse than an unreachable fallback."* Its audit then found the register was
being bypassed entirely — `pinned-mechanism` trust was granted from an
inventory row without ever consulting it.

An **integration audit of the merged L1+L2+L3 tree** found four HIGH findings,
three of which were invisible to either branch audit alone: two reclaim callers
could delete a lock while the mechanism was `flock` or indeterminate, and the
owner token was overwriteable by a check-then-act loser, after which the true
holder could not release and the non-holder could.

Then four stages opened in parallel — telemetry, test infrastructure, evidence
contracts, release metrics — and at 16:10 the nine packages were integrated onto
one branch for the first time.

Along the way: an **Anthropic API outage** killed every harness agent while all
three vendor-CLI lanes completed through it, and a **Unison port** was explored
on request and rejected on measurement.

## 2. What went right — with evidence

**Spec-derived tests found what eleven audits missed.** Every test on the lock
package had been written by the lane that wrote the code, asserting the refusal
*code* — which is what the code emits. Circular. One suite derived from the
specification instead immediately failed:

```
not ok 6 uncovered filesystem refuses before acquisition and names its class
  stderr did not contain network; actual stderr: FM_LOCK_FS_UNSUPPORTED
```

The spec requires, twice, that this refusal name *the path, the detected class,
and the classes that are covered.* The implementation names none of them. The
test is committed **red**, because adjusting it to match the code is the defect
the discipline exists to prevent.

**The Unison question was settled by counting, not arguing.** Three lanes: an
advocate, a skeptic, and an empirical lane whose only job was classification. It
inventoried **97 distinct evidenced failure mechanisms** and found **3 (3.09%)**
that a language or runtime would have prevented — an upper bound, because all
three require rehoming state into transactional storage. *"A transliteration
that continues to coordinate through files, Git, and shell commands prevents
0/97 by language choice alone."* **53.6% were logic and specification errors**,
where the code did exactly what its author intended and the intent was wrong.
And the two strongest pro-port arguments — the `mkdir` non-atomicity and the
compaction race — were **already fixed in this repository** with `flock` and a
single lock spanning append and compaction. The races indicted a hand-rolled
durability layer, not the language.

**The derived inventory caught four branches at once.** Merging six branches,
crlf's inventory test named exactly the four bash-shebang files that had landed
`100644` — `lib/lock.sh`, `lib/liveness.sh`, `lib/stall.sh`,
`tests/selftest-test-infrastructure.sh` — from four different lanes. Some lanes
set the bit on their new libraries and others did not. A hardcoded count could
not have caught that; a derived one did, across a merge.

**Telemetry cannot block a merge, proven rather than asserted.** With the event
log made unwritable, the gate still returns PASS at exit 0 and records
`emission_failed` in its own result. The FAIL direction is likewise unchanged.

**Skeleton-first writing saved rounds.** Four agents died mid-write; only the one
that had written incrementally preserved anything. Changing the instruction from
"write as you go" to *"create the skeleton as your first action, fill each
section in place"* — mechanical rather than aspirational — and every subsequent
lane's work survived its death.

## 3. What went wrong

**Fix rounds carried new defects, repeatedly.** L1's rework closed six findings
and introduced three. crlf's round 2 fixed one family and left the identical
defect in the other two. This is the release's own documented pattern (11 of 12
closure claims previously) reproducing live, four times in one day.

**My own errors, itemised.** `git update-index --chmod=+x` followed by
`git add` on the same path silently reverts the mode; I verified against the
index, reported green, and the commit carried `100644` until an audit caught it.
`pgrep -f` matched its own command line, so I reported a lane "RUNNING" that had
finished. I hit the documented WSL inline-heredoc trap **four times**, in the
file I wrote warning about it. I mis-partitioned round L3, assigning it a task
whose function had to live in a file I had forbidden it to edit, so four call
sites invoked a function that did not exist. And a reaper I wrote
false-positived on **both** of its first two runs — once against a live
interactive session, once against a healthy lane blocked on a model response.

**A premise was false when written.** `round-ownership-default` asserted
`DURABLE_ENABLED` had "exactly two occurrences, at `:66` and `:148`." Measured:
one, at `:66` — and one at the planning base too. Nobody ever ran the grep.
Same class as the three documents carrying three different exec-bit counts.

**Nine lane strandings, none caught by the mechanism responsible.** A vendor CLI
suspended by `SIGTTIN` after self-updating, sitting at `STAT=T` with zero CPU
for eleven minutes while a `pgrep` watchdog called it alive. Agents backgrounding
a round and ending their turn — **twice, with the prohibition stated verbatim in
the brief.** A lane exhausting its turn budget mid-work. An audit lane sitting
21 minutes having never launched its vendor. Four agents dying mid-write.

**And 77 minutes of dead time**, because I left one lane running instead of five
before a turn ended. I cannot self-schedule; a single lane finishing means the
box idles until the next turn.

## 4. Standing rules that came out of today

1. **Enumerate exclusions, not inclusions.** An inclusion list can be relocated
   out of; five rounds proved it. An exclusion list covers what does not exist
   yet, and each entry must carry the reason a reviewer can falsify.
2. **A premise states behaviour and carries its check command.** Never a line
   number — those expire on the next edit. Never an unrun count.
3. **Derive tests from the specification, not the implementation.** A test
   written by the author of the code asserts what the code does.
4. **Write the skeleton first, fill in place.** Not "as you go."
5. **Liveness is state and CPU, never existence.** `pgrep` and `kill -0` match a
   suspended process identically to a running one.
6. **Every new gate lands in shadow mode**, promoted only after ten of our own
   runs with no false positive.
7. **Dogfood in the session that produces it** — and re-baseline the premises of
   every package downstream, because the codebase moves while the plan executes.
8. **Saturate every lane slot before ending a turn.**
