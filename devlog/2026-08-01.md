## Session: fresh-machine bring-up, a missing dependency, and the slop purge

### 1. What actually happened, in order

A new machine, a cold resume, and a resume that started from a stale premise.
The operator's own notes said PR #1 was ready to merge pending vendor logins.
That was eighteen days old and wrong in every particular: PR #1 was closed,
`main` had moved hundreds of commits past it, and the real entry point was
`RESUME-2026-08-01.md` plus the session store. The store had to be pointed out
by a human, because `CLAUDE.md` — the file every agent loads first — never
mentioned it.

Bring-up on WSL then found three controls that assumed a root checkout.
`env/bootstrap-wsl.sh` wrote symlinks into root-owned `/usr/local/bin` with a
bare `ln -sf`; under `set -e` the first `EACCES` killed the run before its own
closing `install.sh` and `tool-check` steps, while still exiting 0, so it looked
finished. `tools/lanectl.sh` hardcoded `/root/.foreman-lanes` and `/root/fm-wt`,
the second with no override at all. And `tools/ci-local.sh` stripped the lanectl
header by its fifth column instead of its first, so the lane-starvation warning
fired on every run including with zero lanes.

Then the real find. The full suite failed **102 tests across 11 files** locally
while CI was green on the same commit. Every failure carried the same line:
`FM_LOCK_UNAVAILABLE no trusted-positive mechanism available`. The lock library
was fail-closing, so none of those tests exercised the code they name. Cause:
`strace` was not installed, and the syscall evidence class is the only one that
can license a lock mechanism as `atomic` — flavour licenses nothing, contention
can license only `non-atomic` or `unknown`. On Ubuntu 26.04, where `mkdir`
resolves to uutils and is permanently distrusted, a host without `strace` has no
trusted mechanism at all. One `apt install` took the suite from 102 failures to
604 pass / 0 fail, on identical code.

That exposed a structural gap: dependencies were stated in three places nothing
ever compared — the manifest that calls itself the source of truth, the
`must_*`/`should_*` arrays in `tool-check.sh` that embed a mirror of it, and the
install routes in `bootstrap-wsl.sh`. `dependencies/` now holds the complete
list and a drift checker that fails when the three disagree.

A five-member council — four Claude agents and GPT via codex, chosen because
this repo's own invariant forbids same-vendor review — then audited the whole
tree. It returned roughly 25 documented contradictions and one mechanical cause
for the evidence duplication. The purge followed: 29 byte-identical files
deleted, three of four competing resume documents deleted, root markdown down
from 13 files to 7, and a hygiene gate to stop it regrowing.

### 4. Standing rules that came out of today

- **A dependency that nothing installs and nothing reports is invisible twice.**
  `strace` was load-bearing, absent from the manifest, absent from the
  provisioner, and unreported by the readiness check. The host said READY and
  failed 102 tests. Declare it, install it, report it — or it is not a
  dependency, it is a coincidence.
- **Presence agreement is not tier agreement.** A reconciliation that compares
  names will pass two records that disagree about whether a host is ready.
- **Search `docs/research/` before treating a measurement as a discovery.**
  Twice today a documented finding was re-derived at cost.
- **A record with a number and no command is an assertion of authority the
  document has not earned.** Every stale count found today was a bare literal.
- **Enforcement hung off a gate that cannot fail is decoration.** Three of the
  nine gates in `ci-local.sh` have no FAIL path at all.
