## 4. Standing rules that came out of today

- Build a Council bundle only from committed SHAs. Require
  `base_sha != head_sha` and a real diff content hash before review.
- Capture Codex final message alone. Keep stderr separate. Treat transcript
  contamination as inadmissible, not as a soft failure.
- Bind localization claims to the exact Council inventory row and to named
  protocol or ownership sections. Do not match cross-row status tokens or
  generic prose words.
- When docs-check fails, inspect the full tool log. Do not trust a tailed
  markdownlint slice as the complete finding surface.
- Treat every admissible Council `changes_requested` finding as an
  engineering defect that still needs correction. A majority advisory
  approval does not cancel that work. Council advice remains advisory
  input only.
- Guard "not whole subtree" claims with injected negative controls. A set of
  literals against only the current file is not sufficient. Prefer a path
  predicate that rejects root and wildcard-first-segment forms, not only the
  examples someone listed.
- When a rework adds `@test` blocks, set `tests/baseline.tsv` to the exact
  live total. Shadow mode hides a stale lower baseline because it accepts
  `pass >= baseline`.
- After every product commit, rewrite current status and resume instructions
  so they no longer say the work is uncommitted. Keep pre-commit claims only
  as historical notes.
- Parse markdownlint JSONC with a fail-closed decoder over the `ignores`
  array only. Do not scan raw quoted tokens across comments or unrelated
  properties.
- Keep Council advice outside release authority. Only Foreman audit, check,
  and merge gates decide release eligibility.
