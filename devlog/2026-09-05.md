# 2026-09-05

Written from the session's evidence bundle. This session made one documentation commit and changed no product code.

## 1. What actually happened, in order

A Grok 4.6 implementation round (`council-binding-20260905`, pueue task 1455) printed `foreman-launch: unshare unavailable/failed (availability probe) -- DEGRADED`. A read-only investigation followed the XML assignment in `~/Moriarty/deliverables/foreman-grok-4-6-pidns-deep-research-prompt-2026-09-05.xml`.

The exact probe was reproduced with captured stderr and a syscall trace. The single failing call is `unshare(CLONE_NEWNS|CLONE_NEWPID) = -1 EPERM`. The caller is uid 1000 with an empty capability set. The shipped binary produced the same trace. Variants with `--user --map-current-user` succeeded.

The archived design record showed that the July verification ran as root. The strong path degraded when Foreman moved to user `charl` in August. The Grok 4.6 model card was reacquired, digest-verified, and read on all 42 pages. The report and receipts landed under `docs/research/`.

## 3. What went wrong

| What it claimed | What was true |
|---|---|
| README: "verified unprivileged on this WSL2 host" | The design record says `wsl -u root` and "non-root user was NOT probed". |
| README: `systemd-run --scope --collect` kills remaining members | Scopes have no main process. `--collect` only unloads the unit record. |
| The launcher "owns a spawned command's whole process tree" | On POSIX it does not signal the group after normal exit. |
| v0.4.0 notes: the host does not permit unprivileged PID namespaces | The host permits them through a user namespace. The flag list does not ask for one. |
| Setup reported READY for the lane | Setup has no containment row. READY covers tools and authentication only. |
| The degraded marker is "never silent" | It reaches only the stream file and the pueue log. No event, heartbeat, or gate sees it. |

## 4. Standing rules that came out of today

- A capability probe that collapses to a boolean must also record exit status and stderr.
- A guarantee verified as root is not verified. Record the uid of every empirical containment test.
- A degraded containment state must appear in the ownership event, not only in a log line.

## 5. Where things stand

Diagnosis complete. No product code changed. The Grok implementation lane still runs degraded on this host. The remedy (user-namespace flags in the Node launcher, resolver order, fail-closed admission) is designed in D7 of the report and awaits an implementation round with the destructive tests under operator approval.

## Addendum: the remedy landed the same day

Three implementation rounds ran on the Codex lane in separate worktrees under run `pidns-remedy-20260905`: the launcher package, the queue and Setup row, and the lane-run integration. The architect re-ran every verification and merged each lane into `main`.

| Check | Evidence |
|---|---|
| Node launcher strong path on this host | `capability=posix_pidns_userns_strong`, child `inner_pid=8`, pid namespace differs from the host, exit passthrough 7, timeout 124 |
| Refusal path | `env PATH=/nonexistent` run prints REFUSED, exit 125, record `tag: Refused` |
| Setup row | `containment` renders DEGRADED or ok and never changes READY |

What went wrong during the rounds:

| What it claimed | What was true |
|---|---|
| The launcher worktree verification failed typecheck, tests, and build | The worktree had no `node_modules`. After `npm ci` every step passed. |
| Codex reported clean runs through `node --import tsx` | Its sandbox could not open the `tsx` IPC socket. The architect re-ran the literal commands. |
| The lane-run round passed all 39 bats cases | On a host with a built Bun binary two PATH-shim cases used that binary instead of the shim. The tests now pin an empty tool root. |
| `FOREMAN_LAUNCH_IMPL=bun` was a working fallback | The Bun binary rejected the new flags as unknown, so an approved degraded round never spawned its command. The flags are now passed only to a launcher that produced a capability record. |
| The merged tree passed `npm test` | The architecture policy pins `lane-run.sh` by digest and rejects any change to `watch.sh`. Both are now re-pinned as recorded legacy debt. |
| `npm run policy-check` verifies the change | Without `--base` it returns `schema_mismatch` on the baseline commit too. `check --base d85b895` is the real gate and passes. |

Measured on this host after the merge: cancelling a strong round with SIGTERM left zero survivors from a `setsid` escapee and a double-forked sleeper.

Standing rules: a worktree verification result is invalid until the worktree has its own installed dependencies. A change to a pinned legacy script is a policy decision, and the pin update must say why.

## Addendum: the approved experiments

The operator approved the D7 experiments after the merge. All five ran against test-owned processes only. Receipts: `docs/research/foreman-pidns-degradation-2026-09-05-receipts/approved-tests-2026-09-05.txt`.

Nothing in the D7 design remains untested. The only claim these results retract is the idea that a transient service could stand in for a security boundary. It cannot.
