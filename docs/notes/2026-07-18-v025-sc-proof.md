# v0.2.5 prevention criteria — proof record (2026-07-18)

The six SC criteria added by the 2026-07-18 plan audit, each proven either
by a live architect-run demonstration or by permanent merged tests. Suite
at `883e77b`: 245 tests, all green, docs-check clean.

## SC-A — agent-stop survivability: PROVEN LIVE

A `--round` unit was enqueued through `lane-queue.sh add misc` (pueue
daemon-owned); the dispatching shell exited immediately after receiving
the task id. Twenty seconds later, with no agent involved, the event log
alone showed the complete round:

```text
{"type":"prompt"} → {"type":"ownership"} → {"type":"state"(verifying)}
→ {"type":"round_done","exit_code":0,"gate_rc":0,"report_fresh":true}
```

The report artifact existed with attempt-fresh content and pueue reported
the task Done/Success. Zero manual resumes. (Transcript in the session;
reproducible with any trivial round.)

## SC-B — whole-round ownership: permanent tests

- `tests/launcher.bats` kill-shot (taskkill launcher_pid → whole tree
  reaped incl. grandchildren) and nested-launcher reap.
- `tests/lane-run.bats` gate-phase ownership-pid refresh (F2 rework): the
  POSIX group-kill targets the gate's own pgid, and the gate runs under
  the launcher so a kill during VERIFYING reaps the gate tree.
- Watch v2 classifies a killed round WAITING_CHILD/AGENT_ABANDONED, never
  SUCCEEDED (`tests/watch.bats` T4b cases).

## SC-C — bounded auto-resume: permanent tests

`tests/lane-supervise.bats`: abandoned lane resumed once and completes; a
never-completing round stops after exactly `durable.resume_max_attempts`
resumes + ONE terminal `abandoned` alert (no N+1th, asserted across two
consecutive sweeps); SIGTERM-mid-sweep releases the supervise lock.

## SC-D — stale-report immunity: permanent tests

`tests/lane-run.bats` --round SC-D case: a report older than this round's
prompt event never satisfies the terminal predicate — no round_done, an
alert instead. Gate-fail case likewise never emits round_done.

## SC-E — no concurrent writers on resume: permanent tests

`tests/lane-supervise.bats`: a lane with a live pid or a held
`.harness/lane.lock` is never resumed (ALIVE noop); the per-run
`.supervise.lock` serializes sweepers.

## SC-F — completion provable without the agent: permanent tests + SC-A

Watch v2 and lane-supervise derive every classification from the event
log + checkpoint refs + heartbeat file alone (`tests/watch.bats` F5 pair:
log-silent+hb-advancing → VERIFYING, both-quiet → STALLED; SUCCEEDED
requires round_done with gate_rc 0). The SC-A transcript is the
end-to-end instance: completion read from the log with the agent absent.

## Residual limits (honest)

- T5b real-vendor concurrency verdict UNVERIFIED (grok CLI absent); caps
  stay grok=1 codex=1.
- Launcher-absent lanes are outside auto-resume scope (no ownership
  event; deliberate, conservative).
- POSIX build carries the documented no-kernel-cascade asymmetry; the
  -pgid reaper rule is doctrine, enforced in code where lane-run owns the
  kill.
- `[audit.policy]` keys are wired through config but consumed by nothing
  until v0.3.0 (documented as such).
