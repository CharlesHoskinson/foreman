## Foreman v0.2.9.0 accomplishments

### Release identity

Release name: `Total Georgecall`.

Annotated tag `v0.2.9.0` targets exact commit
`fbe23257fc389036d6feaa8f38e7b377f3106406`.

The product boundary is the bounded Council preflight executable. The OpenSpec
package is `openspec/changes/council-v029-preflight-release/`.

### Runtime and package architecture

The release ships Node.js 24, TypeScript, Effect, and one self-contained ESM
executable named `council-preflight`.

The executable does not load workspace TypeScript source at run time.

The eight Council packages are:

1. `schema`
2. `domain`
3. `application`
4. `platform-node`
5. `runtime-node`
6. `adapter-grok`
7. `adapter-claude`
8. `adapter-codex`

Shipped capabilities across those packages include:

- closed schemas
- pure domain logic
- prompt preflight
- schema lowering
- provider health
- ready tokens
- process execution
- artifact verification
- redaction
- canonical JSON
- hashing

### ACE Profile 1 preflight

Council compiles the Attempto Controlled English contract before a provider
starts.

Shipped ACE behavior includes:

- Profile 1 parsing
- semantic lint
- closed lexicon
- canonical prompt construction
- compile-before-provider ordering
- fail-closed handling of malformed input

A compile failure returns a typed prompt failure and starts no provider
process.

### CLI and security bounds

The executable reads one bounded closed request from stdin. It writes one
strict provider-neutral result to stdout.

Shipped bounds cover:

- CLI input
- output
- error
- argument
- resource
- time
- artifact
- observed diff
- temporary-file
- secret-safety

Failures are typed and secret-safe for invalid input, provider failures,
timeouts, output limits, and unsupported Google dispatch.

### Provider adapters and path rules

Google fails closed before dispatch because Gemini is absent.

Bounded Grok, Claude, and Codex adapters ship.

Relative host paths normalize once against the CLI invocation directory.
Absolute lexical paths stay preserved. The provider executable value does not
change.

The canary materializer binds the exact challenge nonce in the response
schema. The host still verifies nonce equality after terminal classification
and strict response decoding.
