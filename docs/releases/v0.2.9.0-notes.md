# v0.2.9.0 — release notes (draft)

Drafted while the release is still open. Every claim here must be re-derived
before the tag; the commands are given so that is cheap.

## Tier 2 of the regression harness was specified and built. It has never been run

Tier 2 is on-demand vendor research: 8–12 locked specs carrying seeded defects,
run three times per condition against a pinned vendor model, reported with a
percentile bootstrap confidence interval and an explicit rule that a difference
smaller than the measured variance is `inconclusive` rather than a finding. It
is non-gating by specification and has no automatic trigger — no CI workflow, no
commit hook and no release script invokes it, and a trigger-absence scan with a
planted-hook positive control ships alongside it.

What exists in v0.2.9.0 is the machinery and its fixture-driven tests: the
bootstrap interval, the inconclusive rule, model-pin drift invalidation, the
zero-denominator rule, and the declared per-tier cost and cadence budgets.

What does not exist is a live adapter, a locked spec set, a chosen model pin, or
**a definition of what the per-spec score in [0,1] measures** — that last is a
specification gap, not an implementation gap, and it is the reason firing Tier 2
was never really a spend decision. **There are no Tier 2 results in this
release. Any Tier 2 number attributed to v0.2.9.0 is fabricated.**

The declared Tier 2 cost budget of USD 18 is a ceiling asserted before any
measurement, not an estimate. Treat it as a spending cap. Foreman cannot
currently measure vendor cost at all: every vendor CLI reports
`source: "unavailable"`, so a real run would compute its budget check from a
figure the adapter invented (obligation 96).

Firing Tier 2 requires a maintainer to authorise real vendor spend. That
authorisation has not been given.

## Scope changes

Two packages were **withdrawn**, archived with a `WITHDRAWN.md` giving the
reason and what must not be lost:

- `wsl-ci-parity` — its premise, that the bats suite runs on no CI, is
  measurably false. Five workflows exist and `gates-linux` gates the suite.
- `wsl-seam-doctrine` — its Docker task is direction-reversed against the
  project's own provisioner, its exec-bit task was delivered more strongly by
  `crlf-extensionless-hardening`, and its design census was wrong by 463 files.
  Three of its five items remain live and are named in its `WITHDRAWN.md`.

Two packages were **parked as v0.3.x candidates**, each with a `PARKED.md`:
`spec-triage-gate` and `foreman-discover-lane`. Both lack a checkable contract
rather than an implementation. Note the cost: their sibling
`captured-facts-convergence` has already landed, and its shipped doctrine refers
to a discover lane that will not be built in this release.

One package was **split**: `workload-fit-accounting`. Its report reader is
implemented; its architect-kept doctrine remains open.

## What the suite gates, and where

The bats suite gates on Linux (`gates-linux`, `FOREMAN_CI_BATS: "1"`), on pushes
to `main` and on every pull request. It does **not** gate on Windows: that
workflow sets the flag to `"0"` and runs a two-file non-gating probe instead.
One of those two files fails there — the exec-bit inventory reads the index mode
as empty under Git Bash — so enabling the gate would turn the workflow red on a
test-portability defect rather than a product defect. Tag criterion 2 is
narrowed to Linux on that evidence.

Re-derive with `grep -rn FOREMAN_CI_BATS .github/workflows/`.
