# v0.2.8.2 release notes

Status: release candidate at merged record commit
`d9eafbb17bcf0d968d8b4c6998ce7476d60dc8c3`. Replace this status with the tag
date and final commit only after the three criteria in `checklist.md` pass on
merged `main`.

## Why this release exists

Foreman had spent most of its lane runs on Foreman itself. The v0.2.9 plan
expanded that loop with formal, graph, governance, and statistical work before
Foreman had completed one external implementation. v0.2.8.2 stops that release
and uses an external Gobox pilot as the forcing function.

The withdrawn work is preserved by annotated tag `v0.2.9-preserve`, which
targets `04f369541febf648ef39dcb8fedd930e8b600d3f`. The tag is a recovery point,
not an active roadmap.

## Foreman portability changes

Foreman PR [#7](https://github.com/CharlesHoskinson/foreman/pull/7) merged as
`525cfb050df8afccdad770b8b3aefb79bb0f8183`.

The merge:

- selects an exact soft-mode worktree from the worktree index when hard-mode
  `meta.json` is absent;
- keeps pristine-commit archive verification;
- detects target-owned Make and Go gates;
- separates the Foreman tool root, target repository root, target worktree,
  and run-scoped SessionDB;
- runs workers and gates in the selected external worktree;
- resolves Foreman readiness, launcher, and WSL resources from the Foreman
  checkout;
- documents the external-target operating boundary;
- fixes a Linux trace expression that failed when a generated target path
  contained the letter `n`.

The PR added or updated focused Bats coverage for external checks, target-root
selection, session isolation, lane working directories, and the trace parser.

## Linux NATS coverage

Foreman PR [#10](https://github.com/CharlesHoskinson/foreman/pull/10) merged as
`09e07159ef94b945a6acc2b6c1333864d13291ea`.

The Linux workflow previously lacked `nats-server` and `nats`, so all 12 NATS
integration tests were skipped. The workflow now installs checksum-pinned NATS
Server 2.14.4 and NATS CLI 0.4.0 archives, verifies their exact versions, and
runs the integration slice. All 12 NATS tests passed at PR #10 head
`af2762c9b1d2989d50d3efe2963ea9f97119a3c0`; both Linux and Windows workflows
completed successfully.

## Deterministic formal-runner assets

The first exact-main Windows run after PR #12 failed before model evaluation.
Quint 0.32.0 tried to discover its Rust evaluator through the unauthenticated
GitHub Releases API, received a rate-limit response, and classified all 19
commit-tier rows as `ERROR`. The models did not produce counterexamples.

Release PR [#14](https://github.com/CharlesHoskinson/foreman/pull/14) removes
that hidden first-run dependency. The Linux, Windows, and standalone formal
workflows download the evaluator from its stable release asset URL, verify the
publisher-recorded SHA-256 digest, and place it in Quint's versioned cache
before a model runs. PR #14 Windows run `30802535713` passed in 5 minutes 4
seconds. Its uploaded formal report records 19 rows run, 19 matched, and 0
failures. Both standalone formal runs on the PR head also passed.

## External-portability defect list

The pilot produced this backlog:

| Defect | v0.2.8.2 disposition |
|---|---|
| Soft checks required hard-mode `meta.json` | Fixed in PR #7 |
| Soft worktree selection was ambiguous | Fixed with exact index selection |
| Foreman tool root and target root were conflated | Fixed in `lane-run.sh` |
| Target checks could fall back to Foreman-specific documentation checks | Fixed for Make, Go, and explicit overrides |
| Target state could use the Foreman SessionDB | Fixed with a run-scoped target database |
| Worker and gate working directories could be inherited from the caller | Fixed with the selected target worktree |
| Linux mkdir trace parsing rejected paths containing `n` | Fixed before merge |
| Queue readiness can race with a refused enqueue | Open; see `docs/RESIDUALS.md` |
| Harness and report artifacts enter the target worktree | Open; product commit excluded them |
| Changed-file telemetry can mix product and harness artifacts | Open |
| The external matrix contains one repository and one workload | Open by design for this release |
