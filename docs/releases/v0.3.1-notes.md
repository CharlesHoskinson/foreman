# George's Odyssey

Foreman v0.3.1 release candidate

Status: PR-ready release candidate. The measurements in this record bind to
pushed commit `64604d24308b446eaf1102177165622d3ec29167`. This release is not
merged, tagged, or published.

v0.3.1 is one sentence: **session state is portable — one contract, two
implementations.**

## Product

`SessionStore` now has two complete implementations. SQLite remains the
reference implementation. `FilesOnlySessionStore` stores immutable NDJSON
generations and publishes a paired snapshot and projection outbox with one
`CURRENT` switch. Both implementations pass the same 49-case contract.

The CLI selects a backend through the port-owned factory. Production
TypeScript outside `packages/session-store/src` does not import `node:sqlite`
or concrete backend constructors. A boundary test enforces the rule and uses
negative controls for static, multiline, dynamic, and re-export forms.

`fm-session sync` drains a durable desired-state outbox with Effect-based
cancellation, timeout, and bounded retry. Entries use opaque version receipts,
so an acknowledgement cannot delete a newer operation for the same entity.
SQLite updates the row and outbox in one transaction. Files-only updates both
parts in one paired generation.

The delivery guarantee is durable idempotent at-least-once. It is not
exactly-once. A crash after remote success and before local acknowledgement
must replay the batch. A real `MemoryIndex` adapter must make repeated
desired-state operations idempotent. `NullMemoryIndex` remains the only
shipping adapter.

Snapshot import now supports an additive `remap` policy for a non-empty target.
It allocates new IDs per counted kind, rewrites fact and measurement pointers,
renames colliding sessions deterministically, preserves target rows and pending
receipts, and validates the complete result before one atomic commit.

## What does not ship

No external `MemoryIndex` adapter or projection epoch protocol ships in this
release. That work remains assigned to v0.4.0 and must be tested against a live
service.

Files-only writer exclusion is a single-host process claim. It is not a network
filesystem lease. Deployments must use one writer and one drainer for a given
files-only directory.

The Windows Bats program remains BW-004 and is not a release gate. This release
does not claim that the full Bats suite passes on Windows.
