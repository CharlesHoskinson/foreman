### The finding that reorders the spec's sequencing

The spec sequences `FilesOnlySessionStore` (Step 1) before the negative control (Step 2). This plan reverses that, for a measured reason.

Of the 37 cases in `ALL_CASES`, **only 20 take the store factory**. The other 17 — all 15 `hostile/*` cases plus `supersession/fan-in-is-accepted` and `supersession/fan-in-does-not-disable-other-checks` — have the signature `run: () => {…}` and operate on `SessionSnapshot` literals through `findViolations`. They never construct a store.

A backend that does nothing at all therefore passes 17 of 37 cases before writing a line of code. Building the second implementation first and reading a green suite would be exactly the failure mode this branch has already hit four times. The control comes first so that "the suite passes" is a claim with content.

The 20 discriminating cases span nine categories: `roundtrip` (3), `encoding` (2), `identity` (2), `supersession` (1), `obligation` (1), `session` (1), `write` (1), `import` (2), `retire` (7).

```typescript
// ---------------------------------------------------------------------------
// Negative control
// ---------------------------------------------------------------------------

/**
 * The cases that actually construct a store.
 *
 * `ALL_CASES` also contains snapshot-level cases whose `run` takes no factory —
 * every `hostile/*` case and the two `supersession/fan-in-*` cases. Those
 * exercise `findViolations`, not a backend, so they pass against any store
 * including one that does nothing. Only these cases can discriminate a backend,
 * and only these are counted by the soundness gate.
 */
export const STORE_CASES: readonly Case[] = ALL_CASES.filter(
  (c) => c.run.length > 0,
);

/** Contract category of a case name: the segment before the first slash. */
export function categoryOf(name: string): string {
  const i = name.indexOf("/");
  return i === -1 ? name : name.slice(0, i);
}

/** Distinct contract categories with at least one failing case. */
export function failedCategories(report: SuiteReport): Set<string> {
  const cats = new Set<string>();
  for (const r of report.results) {
    if (r.passed) continue;
    cats.add(categoryOf(r.name));
  }
  return cats;
}

/**
 * A control must fail for several independent reasons, not once. Nine
 * categories are reachable by `STORE_CASES`; requiring three means a single
 * over-broad case cannot carry the gate on its own.
 */
export const MIN_INDEPENDENT_STUB_CATEGORIES = 3;

/**
 * A structurally valid but behaviourally empty SessionStore.
 *
 * It satisfies the TypeScript interface and returns well-formed empty values.
 * It is not a mock of a failing store — it is the subtly wrong backend the
 * suite must be able to reject. Every method returns something type-correct;
 * none of them remembers anything.
 */

  snapshot(): SessionSnapshot {
    return emptySnapshot();

  listSessions(): readonly SessionRow[] {
    return [];

  currentSession(): SessionRow | null {
    return null;

    return {
      session_id: sessionId,
      started_ts: endedTs,
      ended_ts: endedTs,
      start_sha: null,
      note: null,
    } as SessionRow;
  }

  addFact(fact: NewFact): FactRow {

  }
```

The second implementation. Predicate 3, and the half of the release sentence that is missing.

**Files:**

- Modify: `packages/session-store/src/index.ts`

**Interfaces:**

- Consumes: `SessionStore`, `NewFact`, `NewMeasurement`, `NewObligation`, `SupersedeResult`, `ImportOptions` from `./port.js`; `SessionSnapshot`, `emptySnapshot`, `SESSION_MODEL_VERSION` from `./entities.js`; `encodeSnapshot`, `decodeSnapshot` from `./sidecar.js`; `assertIntegrity` from `./integrity.js`; `sessionStoreFailure`, `raise` from `./failures.js`.
- Produces:
  - `type FilesOnlyOptions = { readonly dir: string }`
  - `class FilesOnlySessionStore implements SessionStore`
  - `function openFilesOnlyStore(opts: FilesOnlyOptions): FilesOnlySessionStore`

**On-disk layout.** Mirrors `FilesOnlyGraphStore`'s discipline — a `CURRENT` pointer, immutable generations, an exclusive lock — reduced to what a session store needs:

```text
<dir>/
  CURRENT            # regular file: generation filename + newline
  generations/
    <NNNNNNNN>.ndjson  # immutable snapshot in canonical sidecar form
  .store.lock        # exclusive open/publish lock
```

Reuse `encodeSnapshot`/`decodeSnapshot` for the generation body. That is deliberate: the canonical sidecar encoding is already the declared wire form, already byte-stable, and already covered by `encoding/*` cases. A second bespoke serializer would be a second thing to get wrong.

**Write discipline.** Every mutation is: mutate the in-memory `SessionSnapshot`, run `assertIntegrity`, write the next generation to a unique temp name in `generations/`, `fsync` the file, `rename` it into place, `fsync` the directory, then atomically replace `CURRENT`. On any failure the store is left exactly as it was — the previous generation and `CURRENT` are untouched. This satisfies the port's all-or-nothing clause without transactions.

**Identity.** Ids are minted from `snapshot.nextIds`, never from array length. `peekNextId(kind)` returns `nextIds[kind]` without advancing it.

```typescript
/**
 * Files-only SessionStore: second implementation of the port.
 *
 * No database, no network. State is a canonical sidecar document published as
 * an immutable generation, with CURRENT naming the live one.
 *
 * This exists to make the contract falsifiable. A contract satisfied once is a
 * description of its only implementation.
 */
export type FilesOnlyOptions = { readonly dir: string };

export class FilesOnlySessionStore implements SessionStore {
  readonly modelVersion = SESSION_MODEL_VERSION;
  #snap: SessionSnapshot;
  #dir: string;
  #closed = false;

  private constructor(dir: string, snap: SessionSnapshot) { … }

  static open(opts: FilesOnlyOptions): FilesOnlySessionStore { … }

  // reads — pure projections of #snap
  snapshot(): SessionSnapshot { … }
  listSessions(): readonly SessionRow[] { … }
  currentSession(): SessionRow | null { … }
  listFacts(): readonly FactRow[] { … }
  listMeasurements(): readonly MeasurementRow[] { … }
  listObligations(): readonly ObligationRow[] { … }
  peekNextId(kind: CountedKind): number { … }

  // writes — each one: build next snapshot, assertIntegrity, #publish
  beginSession(args): SessionRow { … }
  endSession(sessionId, endedTs): SessionRow { … }
  addFact(fact): FactRow { … }
  addMeasurement(m): MeasurementRow { … }
  addObligation(o): ObligationRow { … }
  closeObligation(id, status, closedTs): ObligationRow { … }
  supersedeFact(id, replacement, reason, at): SupersedeResult<FactRow> { … }
  supersedeMeasurement(id, replacement, reason, at): SupersedeResult<MeasurementRow> { … }
  retireMeasurement(id, byId, reason, at): MeasurementRow { … }
  importSnapshot(snapshot, opts): number { … }
  close(): void { … }

  #publish(next: SessionSnapshot): void { … }
}

export function openFilesOnlyStore(opts: FilesOnlyOptions): FilesOnlySessionStore {
  return FilesOnlySessionStore.open(opts);
}
```

**Every rejection must use the same failure reason as SQLite.** The suite's `assertRejects` compares `reasonOf(e)` exactly, so a files-only store that refuses for the right reason with a different tag fails the case. Read the corresponding `sqlite-store.ts` method before writing each one and reuse its `sessionStoreFailure(reason, …)` call verbatim. The set-once rules (`endSession`, `closeObligation`, supersession columns) and the retire rules (missing target, missing successor, self-retire, already-retired target, retired successor) each have a distinct reason.

```typescript
/**
 * The single backend selection point.
 *
 * Callers ask for "the session store" and get one. Nothing above this module
 * names a backend — that is what makes the port replaceable rather than merely
 * abstract. Modelled on graph-store's openFromEnv.
 */
import { openFilesOnlyStore } from "./files-only.js";
import { SqliteSessionStore } from "./sqlite-store.js";
import { raise, sessionStoreFailure } from "./failures.js";
import type { SessionStore } from "./port.js";

const ACCEPTED = ["sqlite", "files_only"] as const;

export function openSessionStore(
  env: NodeJS.ProcessEnv = process.env,
): SessionStore {
  const kind = (env["FOREMAN_SESSION_BACKEND"] || "sqlite").trim().toLowerCase();

  if (kind === "" || kind === "sqlite") {
    const path = env["FOREMAN_SESSION_DB"];
    if (!path) {
      raise(
        sessionStoreFailure(
          "backend_misconfiguration",
          "FOREMAN_SESSION_DB is required for the sqlite backend",
        ),
      );
    }
    return SqliteSessionStore.open({ path });
  }

  if (kind === "files_only" || kind === "files" || kind === "file") {
    const dir = env["FOREMAN_SESSION_DIR"];
    if (!dir) {
      raise(
        sessionStoreFailure(
          "backend_misconfiguration",
          "FOREMAN_SESSION_DIR is required for the files_only backend",
        ),
      );
    }
    return openFilesOnlyStore({ dir });
  }

  return raise(
    sessionStoreFailure(
      "backend_misconfiguration",
      `unknown FOREMAN_SESSION_BACKEND=${JSON.stringify(kind)}; accepted: ${ACCEPTED.join(", ")}`,
    ),
  );
}
```

- Produces in `outbox.ts`: `async function drainOutbox(store: SessionStore, index: MemoryIndex, opts: { readonly batch: number; readonly maxAttempts: number }): Promise<{ readonly projected: number; readonly attempts: number }>`

**Ripple, stated plainly.** Extending the port means both implementations must satisfy it and both must be covered by new conformance cases. That is the contract working as designed: the suite is the specification, so a port change that does not add cases is a port change nobody checked. Add the cases in this task, not later.

**Delivery guarantee.** The implemented design uses opaque version receipts and
coalesced desired-state records. Drain reads a batch, projects it, and
acknowledges the exact receipts only after the projection resolves. A throw or
timeout leaves the records pending. A crash after remote success and before the
local acknowledgement replays the batch. The guarantee is therefore durable
idempotent at-least-once, not exactly-once.

```typescript
import assert from "node:assert/strict";
import { describe, it } from "node:test";

import { drainOutbox } from "./outbox.js";
import { openMemoryStore } from "./sqlite-store.js";
import { seedFixture } from "./contract-suite.js";
import { NullMemoryIndex } from "./memory-index.js";
import type { EntityRef, MemoryIndex, ProjectionRecord } from "./port.js";

/** Records every key it is handed, so double-writes are visible. */
class RecordingIndex implements MemoryIndex {
  readonly name = "recording";
  readonly seen: string[] = [];
  async project(records: readonly ProjectionRecord[]): Promise<void> {
    for (const r of records) this.seen.push(r.key);
  }
  async recall(): Promise<readonly EntityRef[]> {
    return [];
  }
  async beginEpoch(): Promise<string> {
    return "e1";
  }
  async activateEpoch(): Promise<void> {}
}

/** Fails the first `n` project calls, then succeeds. */
class FlakyIndex extends RecordingIndex {
  #left: number;
  constructor(failures: number) {
    super();
    this.#left = failures;
  }
  override async project(records: readonly ProjectionRecord[]): Promise<void> {
    if (this.#left-- > 0) throw new Error("transient");
    await super.project(records);
  }
}

describe("outbox drain", () => {
  it("projects and acknowledges every queued row", async () => {
    const store = openMemoryStore();
    try {
      seedFixture(store);
      const index = new RecordingIndex();
      const r = await drainOutbox(store, index, { batch: 10, maxAttempts: 3 });
      assert.ok(r.projected > 0, "nothing was queued, so the test proves nothing");
      assert.equal(new Set(index.seen).size, index.seen.length, "a key was projected twice");
      assert.equal(store.listOutbox(100).length, 0, "the outbox was not drained");
    } finally {
      store.close();
    }
  });

  it("does not double-write when a batch fails and is retried", async () => {
    const store = openMemoryStore();
    try {
      seedFixture(store);
      const index = new FlakyIndex(1);
      await drainOutbox(store, index, { batch: 10, maxAttempts: 3 });
      assert.equal(new Set(index.seen).size, index.seen.length, "retry duplicated a key");
      assert.equal(store.listOutbox(100).length, 0);
    } finally {
      store.close();
    }
  });

  it("leaves rows unacked when attempts are exhausted", async () => {
    const store = openMemoryStore();
    try {
      seedFixture(store);
      const index = new FlakyIndex(99);
      const before = store.listOutbox(100).length;
      await assert.rejects(() =>
        drainOutbox(store, index, { batch: 10, maxAttempts: 2 }),
      );
      assert.equal(
        store.listOutbox(100).length,
        before,
        "a failed drain acked rows it never projected",

    } finally {
      store.close();
    }

  it("is a no-op against NullMemoryIndex without erroring", async () => {
    const store = openMemoryStore();

      seedFixture(store);
      const r = await drainOutbox(store, new NullMemoryIndex(), {
        batch: 10,
        maxAttempts: 1,
      });
      assert.equal(store.listOutbox(100).length, 0);
      assert.ok(r.projected >= 0);
    } finally {
      store.close();
    }
  });
```
