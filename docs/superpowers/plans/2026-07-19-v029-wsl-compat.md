**Goal:** Make foreman's already-built WSL protections actually ship, wire, and stay
verified for a fresh WSL2 operator, and harden the Windows↔WSL seam — packaged as
v0.2.9.

**Architecture:** Six packages. P1-P2 close live blockers (POSIX launcher never built
on WSL → silent pidns-cascade loss; 3 extensionless CRLF scripts). P3 adds a WSL
preflight (filesystem/clock/networking/tool-resolution) wired into Setup + lane-start.
P4 persists tool PATH for non-interactive lanes. P5 puts the whole surface under CI
(ubuntu + windows `shell:bash`). P6 codifies the seam doctrine + closes the exec-bit
trap. No change to the frozen launcher-absent degraded path, lane-run's kill logic, or
the durable-lane core.

**Tech Stack:** bash + bats-core, Bun (`build:posix`), GitHub Actions (ubuntu-latest +
windows-latest), `git` attributes/renormalize, `toml_get`/`common.sh`, `docs-check.sh`,
a real WSL2 host for live verification.

## P2 — crlf-extensionless-hardening

**Files:** `.gitattributes`, the 3 extensionless scripts (working-tree line endings +
exec bit), `tests/line-endings.bats`. EARS: `openspec/changes/crlf-extensionless-hardening/specs/line-endings/spec.md`.

**Reframe (Opus audit correction):** this is NOT a live fresh-clone CRLF bug — the 3
scripts' git INDEX blobs are already LF (`git ls-files --eol` → `i/lf`, confirmed). They
only show `w/crlf` on a checkout with `core.autocrlf=true` (Git-Bash's default, and a
shared `/mnt/c` Windows checkout read from WSL) — a fresh ext4 clone checks them out LF,
no bug. So P2 is: (a) harden the autocrlf-seam so that class of checkout never produces
CRLF, and (b) fix the same 3 scripts' exec-bit trap (they are git-mode `100644` and
invoked by direct exec, e.g. `scripts/review-package …` from `SKILL.md`, never `bash …`;
`install.sh`'s chmod glob never reaches `skills/superpowers/**`) — this is P6's exec-bit
concern's concrete instance, fixed here since it shares the same 3 files.

### Task P2.1 — index-LF assertion + autocrlf-seam hardening + exec-bit fix (TDD)

- [ ] **Step 1: Write the test** (`tests/line-endings.bats`) — for every tracked file
  whose first line is a `bash`/`sh` shebang: (a) assert its git INDEX is LF via `git
  ls-files --eol` (`i/lf`) — this is non-vacuous on every host, including a fresh ext4
  clone, since it inspects the index rather than the working tree; and (b), only on an
  `autocrlf=true` checkout, assert the working-tree bytes contain no `\r`.

```bash
# tests/line-endings.bats
@test "every tracked bash/sh shebang script is LF in the git index" {
  cd "$BATS_TEST_DIRNAME/.."
  local bad=0
  while IFS= read -r f; do
    [ -f "$f" ] || continue
    head -c2 "$f" 2>/dev/null | grep -q '#!' || continue
    head -1 "$f" | grep -qE 'bash|/sh( |$)|env sh' || continue
    # index-based: non-vacuous on every host, including a fresh ext4 clone
    if ! git ls-files --eol -- "$f" | grep -q 'i/lf'; then
      echo "index not LF: $f"; bad=1
    fi
  done < <(git ls-files)
  [ "$bad" -eq 0 ]
}

@test "every tracked bash/sh shebang script is LF in the working tree on an autocrlf=true checkout" {
  cd "$BATS_TEST_DIRNAME/.."
  # only meaningful when this checkout normalizes CRLF->LF on check-in (Git-Bash /
  # shared-/mnt/c default); skip elsewhere rather than false-failing on ext4.
  [ "$(git config --get core.autocrlf 2>/dev/null)" = "true" ] || skip "not an autocrlf=true checkout"
  local bad=0
  while IFS= read -r f; do
    [ -f "$f" ] || continue
    head -c2 "$f" 2>/dev/null | grep -q '#!' || continue
    head -1 "$f" | grep -qE 'bash|/sh( |$)|env sh' || continue
    if LC_ALL=C grep -lU $'\r' "$f" >/dev/null 2>&1; then
      echo "CRLF in working tree: $f"; bad=1
    fi
  done < <(git ls-files)
  [ "$bad" -eq 0 ]
}
```

- [ ] **Step 2: Run to verify the RED state.** On this host (ext4 clone) the index
  assertion already PASSES — the index was never the bug, so this is a hardening/
  regression guard here, not a red-first proof. The red-first proof is the SECOND test,
  run on a Git-Bash/`autocrlf=true` checkout (that's the only place the 3 extensionless
  scripts are `w/crlf` today) — confirm it fails, naming the 3 scripts.
- [ ] **Step 3** — Extend `.gitattributes`: add `* text=auto eol=lf` (catch-all) ABOVE
  the existing rules; add a binary carve-out `*.png *.jpg *.jpeg *.ico *.pdf *.exe
  binary` (insurance against `text=auto` mis-detecting a NUL-free binary); keep `*.sh
  *.bash *.bats text eol=lf`; add explicit `eol=lf` lines for the three extensionless
  scripts (path globs, mirroring the vendored `hooks/session-start` rule); add `*.bat
  *.cmd *.ps1 text eol=crlf` (genuine Windows files). Then run `git add --renormalize .`
  — expect this to be a near-no-op for line endings (the index blobs are already LF); it
  may only pick up newly-attributed files the broadened catch-all now covers.
- [ ] **Step 4: Run to verify both tests pass** — the index test passes everywhere; the
  autocrlf working-tree test now passes on the Git-Bash/`autocrlf=true` checkout too
  (`git ls-files --eol` shows `w/lf` on the 3 scripts there); `git status` clean after
  commit.
- [ ] **Step 5: Exec-bit fix** — `git update-index --chmod=+x` the same three scripts
  (committed mode `100644` → `100755`) so a fresh ext4 clone can direct-exec them without
  `Permission denied`. Verify with `git ls-files -s` (mode `100755`).
- [ ] **Step 6: Commit** `git commit -m "fix(wsl): autocrlf-seam hardening (.gitattributes eol=lf coverage) + exec-bit fix for 3 extensionless SDD scripts"`.
