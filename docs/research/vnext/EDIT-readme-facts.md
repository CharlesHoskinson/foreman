## 5. Single most misleading sentence

**Sentence:** “Hard mode's loop is `INIT → PLAN → IMPLEMENT → CHECK → EVIDENCE → AUDIT → GATE → PR`, fail-closed at every stage:” (`README.md:240-241`)

**Why it is most misleading:** It is the document’s central safety claim, stated
without qualification immediately before the stage table. Yet the gate checks
only whether an audit file exists and contains an allowed verdict
(`skills/foreman/scripts/gate-eval.sh:12-14`, `:43-47`). Five ordinary
`audit-run.sh` failure paths can exit without replacing that file
(`skills/foreman/scripts/audit-run.sh:90-112`). After a rework round, a stale
APPROVED or WARNING verdict can therefore satisfy the gate for a different
diff. “Fail-closed” tells a release operator precisely the opposite of the
shipped failure mode.

**Rewrite:** “Hard mode exposes the ordered `INIT → PLAN → IMPLEMENT → CHECK →
EVIDENCE → AUDIT → GATE → PR` loop, but it is not fail-closed across audit
rounds: verdict files are not freshness- or diff-bound, and a failed re-audit
can leave a prior verdict eligible.”
