Cross-vendor coding agents

The smart model judges. Other models type.

Two modes, one skill

Soft mode is the daily driver inside Claude Code. Hard mode adds worktrees, host-side evidence, independent checks, cold-diff audit, and a deterministic merge gate before PR.

Default

Soft mode

Cost-aware architect routing. Five-part specs go to Grok or Codex implementers. The session model emits judgment, not volume. Advisor consults only at commitment boundaries. Works today with install.ps1 / install.sh.

Opt-in

Hard mode

Full loop: INIT, PLAN, IMPLEMENT, CHECK, AUDIT, GATE, PR. Security-critical enforcement lives in bash scripts, not prompts. Worker vendor must differ from orchestrator. Run state lives under ~/.foreman/runs/, outside every worktree.

Pick hard when workers are untrusted or autonomous and the deliverable is a PR. Pick soft for interactive multi-task sessions. Config key: mode in .foreman/config.toml.

Roles

Four contracts. Cross-vendor separation is intentional: same-family blind spots are the failure mode you are buying insurance against.

Role Who Owns Never
Orchestrator Session that invoked /foreman Requirements, specs, routing, verification, gate judgment Routine implementation when a worker lane is available
Worker Other-vendor CLI (default Grok) Context-free implementation of the five-part spec Silent architecture changes; claiming green tests as evidence
Auditor codex-auditor (GPT-5.6 Sol, read-only) Cold-diff verdict APPROVED / WARNING / BLOCKED Implementing; auditing same-vendor worker
Advisor foreman-advisor (Fable / Opus) Short verdicts at commitment boundaries Implementing or rubber-stamping weak plans

Lanes

Route by how much judgment the spec cannot capture. Default cheap and cross-vendor. Escalate deliberately.

Lane Producer Invoke When
Routine Grok 4.5 grok-implementer Spec fully determines the outcome. Default implementer.
Cross-vendor implement GPT-5.6 Sol (high) codex-implementer Race / second implementation, or Grok unavailable.
Audit (default) GPT-5.6 Sol (high, read-only) codex-auditor After independent checks; Grok worker → Codex Sol auditor.
Judgment Fable / Opus foreman-advisor Architecture, migrations, stuck work, final multi-step sign-off.

Missing CLI returns STATUS: unavailable. Lanes never silently fall back to the host model under another vendor's name. Re-route explicitly.

Five-part spec

Implementers share none of the architect's chat context. If you cannot finish the interfaces or verification section, you are not ready to delegate.

  1. Objective

    What to build or change, and why. One paragraph.

  2. Files

    Exact paths to create, modify, or leave untouched.

  3. Interfaces

    Signatures, types, API shapes, anchor IDs, tokens the code must match.

  4. Constraints

    Conventions, stack limits, forbidden refactors, mode notes.

  5. Verification

    Commands the architect will re-run. Reports without command output are incomplete.

Security model

Honest limit: containers share the host kernel. Soft mode uses native CLI sandboxes only. Foreman is defense-in-depth, not a hard isolation guarantee.

Containers (hard mode) share the host/WSL2 kernel — defense-in-depth, not a hard boundary.

Threat Soft response Hard response
Reward hacking Architect re-runs verification Pristine checkout checks; worker claims ignored
Test / CI tampering Diff review + forbidden paths in constraints Hash snapshot + gate forbidden_paths
Same-vendor blind spots Prefer Grok/Codex under Claude architect Worker ≠ orchestrator; audit ≠ worker
Prompt injection Context-free specs; advisor reads code Cold-diff auditor; no MCP in worker
Secret bleed Never paste keys into specs Container gets only worker vendor key

Requirements

Claude Code with Fable (or Opus fallback). Grok CLI for the default implementer. Codex CLI for the default auditor (GPT-5.6 Sol) and optional implement races. Without external CLIs, lanes report unavailable.

Architect doctrine

Project CLAUDE.md pins: minimize architect tokens, five-part specs, independent verification, no silent same-vendor fallback.

Lineage

Foreman is a deliberate merge of two complementary patterns, not a fork of either alone.

Soft routing

Fable Advisor pattern

Architect cost discipline, five-part specs, Grok and Codex implementer agents, advisor at commitment boundaries. Shipped first as a Claude Code plugin by DannyMac180/fable-advisor.

Hard harness

Original Foreman design

Worktrees, host evidence, independent checks, cold-diff audit, deterministic gate, vendor adapters, WSL2 reference environment. Scripts under skills/foreman/scripts/.

Soft mode is production-ready (agents + doctrine). Hard mode ships INIT/CHECK/EVIDENCE/GATE plus host Codex AUDIT; Docker worker IMPLEMENT and full PR automation are still expanding.
