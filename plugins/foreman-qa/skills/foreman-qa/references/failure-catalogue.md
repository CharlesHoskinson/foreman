# Failure catalogue

Each incident is a concrete instance of a check or claim that looked stronger than it was.

| Symptom | Root Cause | Rule that now prevents recurrence |
| --- | --- | --- |
| `tests/run.sh` exited `0` despite policy failures. Source: `tests/run.sh`, result dispatch near lines 433–447; `docs/research/2026-08-06-testing-council/suite-health.md`, shadow-mode discussion. | Shadow mode intentionally emits `RESULT SHADOW mode=shadow policy_failures=N exit=0`; the process status is not the policy verdict. `RESULT ERROR runner_errors=N` is also distinct from pass or fail. | Read the declared `RESULT` token and all named fields. Never reduce the result to exit code alone. |
| A checker reported every run, including clean controls, as a violation. Source: `bugeventlog.md`, fifth checker failure around lines 1570–1575; `docs/superpowers/specs/2026-07-31-v029-release-closeout-design.md`, “Three rules the registry enforces.” | Unanchored `grep "violation"` matched both a violation message and `[ok] No violation found`. Nobody required the predicate to accept known-good input. | In the same run, require NEGATIVE on known-bad input and POSITIVE on known-good input. Reject ambiguous substring predicates. |
| The `rod` lane reported success while leaving a proof comparison that could never become true. Source: `docs/superpowers/specs/2026-07-31-v029-release-closeout-design.md`, “Per package.” | `[[ "$durable_enabled" == "__disabled_for_independent_proof__" ]]` compared runtime state with an impossible literal. No destructive control had shown the check could go red. | Sabotage the predicate, confirm red, restore it, and confirm green; verify restoration independently rather than accepting the lane's report. |
| Four planning-session checks returned false answers in different ways. Source: `bugeventlog.md`, lines 1570–1575; `docs/superpowers/specs/2026-07-31-v029-release-closeout-design.md`, “Three rules the registry enforces.” | One used exit code, one used an ambiguous substring, one was vacuous, and one checked the wrong module. Each predicate was structurally unable to reject its target case. | Prove both polarities and require decision-changing results to be corroborated by a different predicate, mechanism, or actor. |
| A package could report a green test run after selecting no relevant tests. Source: `docs/superpowers/specs/2026-08-06-v030-checkpoint.md`, Section 4; `docs/research/2026-08-06-testing-council/migration-parity.md`. | The `npm test` glob was unquoted; `sh` lacks `globstar`, so `src/**/*.test.ts` was interpreted as `src/*/*.test.ts`. It worked only while no nested `src` test existed, and `node --test` exits `0` on a zero-file selection. | Assert the selected inventory is nonzero and matches an expected count or bound. Empty selection is error, never coverage. |
| The PID-namespace safety path stayed green in hosted CI but failed on hosts capable of running it. Source: `bugeventlog.md`, “Two host-property findings” around lines 3651–3658; `docs/research/2026-08-06-testing-council/suite-health.md`, Section 2.6; `node-runner.md`, Section 4.4. | Hosted CI denied `unshare`, so the path was not taken. A capable host exposed re-exec without the `tsx` loader and failure to resolve `heartbeat.js` when the source was `heartbeat.ts`. | Establish path reachability and required host capabilities before citing CI green as evidence for behavior. |
| Execution-derived review findings held while inspection-derived counts collapsed under checking. Source: `docs/superpowers/specs/2026-08-06-v030-checkpoint.md`, Sections 2–3, together with the measured review comparison recorded for this skill. | Reading created plausible but unchecked counts and descriptions. The measured comparison confirmed five of five execution-derived defect claims and falsified three of three inspection-derived claims, including the asserted zero output-content assertions where 61 existed across 27 of 34 tests. | Rank direct, controlled execution above inspection. Treat inspection as a source of leads and measure before deciding. |
| Seven failing lane-queue tests were published as missing functionality, but the functionality existed. Source: `bugeventlog.md`, “a root cause inferred from test names, published, and wrong,” around lines 3728–3769. | Test names plus a plausible migration narrative replaced inspection of the actual invocations and implementation. The tests used a stale pre-Endstop call form and were correctly rejected. | Treat test names, reports, commits, and PR descriptions as hypotheses. Read the invocation and code, then execute before publishing a cause or deleting work. |
