## How to dispatch a grok lane so it actually works

Measured today across five dispatches — see AGENT_TRAPS §7 for the full table.

```bash
cd /root/fm-wt/integrate
FM_LANE_OWNER=arch bash tools/lanectl.sh launch LABEL -- \
  bash skills/foreman/scripts/lane-run.sh RUN LABEL /root/fm-wt/WT -- \
  bash skills/foreman/scripts/grok-multiround.sh /root/fm-specs/SPEC-x.md --max-rounds 3 -- \
  grok -m grok-4.5 --allow Write --allow Edit --output-format plain --cwd /root/fm-wt/WT
```

- **ONE deliverable per dispatch.** Two empty-burst even when both are well
  specified.
- **Inline every fact.** `--prompt-file` is single-turn: a spec the worker must
  READ before it can WRITE cannot succeed at any `--max-rounds`.
- **Write-first names the real source file**, never a notes/sentinel file.
- Keep specs in `/root/fm-specs/`, outside the worktree.
- Diagnosis is the architect's job and is the actual cost. A five-line change
  already specified to the character is cheaper to write than to delegate.
