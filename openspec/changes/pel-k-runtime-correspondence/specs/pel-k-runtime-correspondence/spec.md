# Audit runtime correspondence and host boundaries

## ADDED Requirements

### Requirement: K09-001 Complete boundary relation

The correspondence register SHALL map every current evaluation operation and continuation component into an explicit boundary relation.

#### Scenario: K09-001-P Accepted behavior

- **GIVEN** All 17 evaluation operations, all continuation fields, and reachable closure graphs.
- **WHEN** Compare related states before and after each exercised semantic transition.
- **THEN** Account for administrative stuttering and preserve every observable field.

#### Scenario: K09-001-N Distinguishing refusal

- **GIVEN** Drop a counter, graph edge, host argument, or ready/already-emitted distinction.
- **WHEN** The same requirement check runs.
- **THEN** Reject the relation and detect the changed observation with a negative control.

### Requirement: K09-002 Host correspondence ledger

The release SHALL classify each claimed host guarantee by its model, implementation owner, and actual evidence.

#### Scenario: K09-002-P Accepted behavior

- **GIVEN** Language suspension, journal persistence, budget grants, native cancellation, and the restored legacy-controller path.
- **WHEN** Audit source-bound traces and existing formal coverage references.
- **THEN** Keep language proofs separate from tested host behavior and unresolved production correspondence.

#### Scenario: K09-002-N Distinguishing refusal

- **GIVEN** Cite historical Quint positive-resume behavior as proof of the current M6 refusal path.
- **WHEN** The same requirement check runs.
- **THEN** Reject the claim and retain the named migration obligation.

### Requirement: K09-003 Mismatch resolution

The program SHALL preserve every semantic mismatch until a reviewed normative decision or corrected implementation resolves it.

#### Scenario: K09-003-P Accepted behavior

- **GIVEN** A K and TypeScript disagreement with an independently specified expected outcome.
- **WHEN** Record and adjudicate the minimal counterexample.
- **THEN** Bind the decision and regression case to the corrected candidate.

#### Scenario: K09-003-N Distinguishing refusal

- **GIVEN** Change the comparator or expected result solely to make the mismatch disappear.
- **WHEN** The same requirement check runs.
- **THEN** Reject acceptance and reopen all affected evidence.

### Requirement: K09-004 Claim boundary labels

The documentation SHALL distinguish complete K profile execution, tested TypeScript correspondence, and mechanized source correspondence.

#### Scenario: K09-004-P Accepted behavior

- **GIVEN** A K1 candidate with all conformance cases and scoped K proofs passing.
- **WHEN** Render the release claim table.
- **THEN** State full-profile K semantics and tested runtime correspondence with exact scopes.

#### Scenario: K09-004-N Distinguishing refusal

- **GIVEN** Describe K1 as a proof of all TypeScript behavior, host safety, or provider truth.
- **WHEN** The same requirement check runs.
- **THEN** Fail documentation review and require the separate K2 evidence before making that stronger claim.
