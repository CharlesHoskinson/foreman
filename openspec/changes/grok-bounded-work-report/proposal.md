# Grok bounded work and report

## Why

Native Grok qualification can produce a valid report without the required edit.
Schema-less coding can also mix progress text with its final answer.
The current adapter does not enforce its declared total token and monetary limits.

## What Changes

- Separate coding from structured reporting under one Foreman effect.
- End coding authority before reporting from immutable evidence.
- Retain Grok 4.6, native account selection, effort, workspace grants, and total limits.
- Reject native dispatch when required hard resource enforcement cannot be established.
- Validate final metadata instead of extracting JSON from progress text.

The recommended process-separated design remains proposed for review.
See `docs/superpowers/specs/2026-09-15-grok-bounded-work-report-design.md`.

## Impact

Affected areas: Grok ACP transport, native admission and boundaries, usage projection, provider qualification, and regression fixtures.
No new scheduler, publication authority, API-key requirement, or model substitution is introduced.
No Moriarty roadmap acceptance changes.
