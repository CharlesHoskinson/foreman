# Change: Return of the ForeDi adoption

## Why

A Pel runtime is useful only when users can install it and complete real workflows.
Legacy dispatch instructions and parallel control loops would preserve the current complexity.
Research sources also need usable navigation and visible freshness.

## What Changes

- Ship a clean Node.js 24 installation, quickstart and working Pel examples.
- Document all six exact profiles without claiming unavailable accounts are ready.
- Migrate representative legacy workflows into one Pel execution path.
- Delete replaced execution behavior and measure net simplification.
- Expose bounded research context, graph provenance and optional Obsidian links.
- Package the working features with support diagnostics and compatible rollback.

## Impact

Extend existing installer, runtime build and orchestration CLI code in TypeScript.
Create adoption tests in `packages/orchestration/src/`.
Add Pel examples under `examples/pel/` and instructions under `docs/guides/pel/`.
Preserve existing event history, authority, credential boundaries and historical decoders.
Retain unfinished v0.5 obligations with their existing evidence.

This milestone depends on M1, M2, M3, M4 and M5.
It consumes their working language, adapters, execution and host evidence features.
It introduces no new execution engine, external service or mandatory vault.

Release name: **Return of the ForeDi**.
The numerical version remains undecided.
The existing release design supplies targets, not completed measurements.
