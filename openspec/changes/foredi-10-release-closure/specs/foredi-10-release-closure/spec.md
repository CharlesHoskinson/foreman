## ADDED Requirements

### Requirement: RC01 Inherited predicates

The release gate SHALL preserve and evaluate all fifteen v050 exit predicates on their designated hosts and the unchanged candidate.

#### Scenario: Missing designated host

- **WHEN** a Windows-only predicate cannot execute
- **THEN** the result is UNCOMPUTABLE and final acceptance fails

### Requirement: RC02 Retained source obligations

The closure register SHALL map every open adoption obligation to its original requirement, owner, evidence, and disposition.

#### Scenario: Restored legacy path

- **WHEN** a restored controller still has active callers
- **THEN** retirement remains incomplete until caller parity and host checks pass

### Requirement: RC03 Fresh simplification evidence

The final candidate SHALL retain the fifty percent required-instruction reduction target under the frozen measurement contract.

#### Scenario: New code and documentation

- **WHEN** source changes after historical C2 measurements
- **THEN** fresh counts are required and historical measurements remain unchanged

### Requirement: RC04 Package and recovery

The final candidate SHALL pass clean archive installation, configured execution, safe support export, and compatible rollback without checkout dependencies.

#### Scenario: Disposable installed candidate

- **WHEN** the package runs in a clean private installation
- **THEN** manifest hashes match and rollback preserves compatible history

### Requirement: RC05 Evidence integrity

WHEN acceptance is evaluated, the gate SHALL reject stale, missing, mixed-candidate, skipped-required, or secret-bearing evidence.

#### Scenario: Source changes after audit

- **WHEN** candidate content differs from the audited content
- **THEN** acceptance fails until checks and independent audit cover the new candidate

### Requirement: RC06 Final provider claims

The release SHALL require live qualification for every advertised native capability cell and all four required credential-management providers.

#### Scenario: Synthetic-only provider result

- **WHEN** a required native provider has fixture evidence only
- **THEN** the release remains unaccepted

### Requirement: RC07 Version and publication authority

WHEN release publication is requested, the existing program SHALL require reconciled version, explicit publication authority, all predicates, and cold audit on one candidate.

#### Scenario: No publication authority

- **WHEN** implementation and tests pass without an authorized publication transaction
- **THEN** the loop stops at a release-ready handoff without push, tag, or release creation

### Requirement: RC08 Scope preservation

The closure work SHALL preserve the production-code deferral and planned M7 implementation disposition without treating either as a completed result.

#### Scenario: Deferred target reporting

- **WHEN** release notes describe the historical production target
- **THEN** the original failed measurement remains and the separate cleanup obligation stays open

#### Scenario: Dual production platform evidence

- **WHEN** the production credential package requests final acceptance
- **THEN** the gate SHALL require separate candidate-bound WSL and Linux qualification receipts and all four provider capability results
- **AND** absent scheduled Windows lifecycle tests SHALL leave WSL platform qualification incomplete
- **AND** isolated restore SHALL block delivery and provider traffic until backend and provider generation reconciliation completes
