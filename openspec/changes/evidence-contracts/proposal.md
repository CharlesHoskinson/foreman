## Why

Four times today across three vendors, lanes exited 0 while producing no real work: a codex audit lane announced its report was ready, checked that the file was absent, and still wrote nothing; a grok council lane wrote one of four required files after 191k tokens and 85 tool calls then waited on a nonexistent background notification; two further grok lanes emitted narration with zero tool calls. In every case the process exit code claimed success. The only signal that distinguished real work from narration was a pre/post git-status write-evidence digest — the same class of check grok-multiround.sh already uses for grok implement lanes alone. Planning, audit, research, and every non-grok vendor currently lack that protection and can narrate indefinitely while being reported successful.

## What Changes

- Make lane success depend on artifacts and their content, never exit code, never agent self-report, never substring matches on agent output — for implement, audit, planning, and research alike.
- Replace the path-level `git status --porcelain` digest as the acceptance mechanism. Write evidence is a **content hash over a declared deliverable set**, paired with a lane-type artifact assertion (existence, non-emptiness, schema validity, validator exit). A path-level digest may remain as one corroborating signal, never as the verdict, and wherever it is used it SHALL use `-uall`. Both residual blind spots are stated in the spec: without `-uall` an untracked directory collapses to one line; with or without `-uall` the digest is blind to content changes within an unchanged status string.
- **`INCONCLUSIVE` describes the evidence mechanism, not the round, and no lane type is exempt from an unchanged comparison.** Where the mechanism failed a planted-write control or the comparison could not be computed, the outcome is `INCONCLUSIVE` and contributes nothing in either direction. Where the mechanism is trusted, an unchanged comparison is a fact — this attempt produced nothing — and the lane-type artifact assertion decides, requiring attempt-fresh production for every lane type. The 2026-07-28 `EMPTY-BURST FAILED` verdict is unreachable because the mechanism that produced it fails the control, and an empty second implement round is not re-admitted as successful.
- Every declared deliverable carries a **required end state** (`present` or `absent`), and the content digest has one **canonical per-path encoding** in which absence is a recorded value. A correct deletion changes the digest exactly as a write does, and is distinguishable from a round that wrote nothing.
- Each lane declares **two evidence roots**: a work root (the worktree it operates on or reviews, which must be a git work tree) and an artifact root (where its required artifacts are written, which need not be). The audit lane's artifact root defaults to the run directory `$FOREMAN_HOME/runs/<run-id>/reports/`, which is outside every repository — the previous single root required the audit artifact to be simultaneously outside the reviewed worktree and inside a git work tree, which nothing satisfies.
- Define **lane-type-specific evidence contracts**. One predicate cannot serve four lane types: an implementation lane changes expected tree content; an audit lane leaves the reviewed worktree unchanged and produces a schema-valid, attempt-bound external verdict; planning and research lanes produce named, complete artifacts. The previous single predicate wrongly rejected a correct audit and accepted a partial package.
- The declared deliverable set is **orchestrator-resolved, non-empty, recorded before dispatch and unforgeable**, and no round is dispatched into a contract that is already satisfied.
- Add a **planted-write positive control**: the mechanism must be demonstrated to detect a known write — including the three verified blind cases — before any of its verdicts is trusted, and the control corpus must be shown to fail the old predicate.
- Generalize the bounded re-prompt / evidence loop from grok-only implement lanes to every vendor (via vendor-adapter-contract) and every lane type, with a loud terminal failure when the round budget is exhausted without a satisfied lane-type evidence contract.
- Capture vendor termination/stop reason alongside evidence results so empty-burst (narration-only) can be distinguished after the fact from cancelled-writes (permission-gate blocks).
- Add a scoped mutation probe stage to checks-run.sh that mutates only diff-touched lines, asserts the suite kills each mutant, and reports survivors as unprotected changed lines; primary cadence is merge-gate (optional on-demand elsewhere), not every commit.
- Treat vendor-adapter-contract and test-infrastructure-hardening as co-requisites: this package owns evidence predicates, the shared evidence helpers, and the mutation-probe stage, not adapter argv shape or the general positive-control requirement.

## Impact

- **Ownership (resolves the dual-ownership finding).** This package is the **sole implementation owner** of `skills/foreman/scripts/lib/evidence.sh` and `skills/foreman/scripts/vendor-multiround.sh`. `vendor-adapter-contract` is a **declared consumer** of both: it supplies `adapter_implement_argv` and `adapter_caps`, and it SHALL NOT define or re-specify the evidence predicates. The same statement appears in `vendor-adapter-contract/proposal.md`. Before this amendment both packages claimed these two files, which would have let incompatible helper semantics land twice.
- **lib/evidence.sh (new, owned here)**: declared-deliverable-set content digest, `-uall` path-level corroboration, lane-type evidence contracts, fail-closed computation errors, planted-write positive control.
- **vendor-multiround.sh (owned here, replaces grok-multiround.sh)**: vendor- and lane-agnostic evidence loop (pre/post content digest, artifact assertion, budget, loud terminal failure), invoking vendors only through vendor-adapter-contract.
- **lane-run.sh / lane-supervise.sh** (or equivalent orchestration entry points): resolve and record the declared deliverable set and lane-type contract before dispatch; capture pre/post evidence and vendor termination reasons for every lane round; feed results into success predicates and reports.
- **checks-run.sh**: add a new scoped mutation-probe stage (diff-touched lines only), wired primarily at merge-gate with optional manual invocation.
- **Downstream gates and status reporting**: must consume the evidence-loop terminal failure state so unsatisfied-contract / budget-exhausted outcomes cannot pass as green, and must distinguish an `INCONCLUSIVE` (untrusted or uncomputable) mechanism from a trusted comparison that failed a round.
- **three-outcome-verdicts**: shares the canonical content-record function used for `tree_sha256`, and supplies the pre-spawn in-progress verdict publish that this package's audit-lane contract relies on to prevent a stale verdict carrying a no-op audit.
- **Cross-package**: depends on vendor-adapter-contract for how each CLI is invoked; does not duplicate test-infrastructure-hardening's general positive-control work, and owns only the planted-write control for its own mechanism.
