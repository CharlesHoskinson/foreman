## T1 — the evidence mechanism (this package is the implementation owner)

- [ ] 1. Implement `skills/foreman/scripts/lib/evidence.sh` in this package. It is owned here and consumed by vendor-adapter-contract; that package supplies `adapter_implement_argv` and `adapter_caps` and SHALL NOT define these predicates.
- [ ] 2. Implement the deliverable-set content digest: for every declared deliverable entry and every path the status enumeration reports as changed within the lane's WORK root, emit one canonical record; digest = SHA-256 of the sorted concatenation. Roots are per-lane and there are two of them (T2.7a).
- [ ] 2a. Implement the canonical per-path record exactly as specified: sorted bytewise-ascending by path; `path\0state\0mode\0hash\n`; states `f`/git file mode/SHA-256 of bytes, `l`/`120000`/SHA-256 of the link target string, `d`/`040000`/64 zeros, `-`/`000000`/64 zeros for a path that does not exist. This is the SAME function `three-outcome-verdicts` uses for `tree_sha256`; implement it once and share it.
- [ ] 2b. Emit an absent-state record for every declared deliverable that does not exist and every path reported deleted, so a removal changes the digest exactly as a write does and a lane that correctly deleted a file is distinguishable from a lane that wrote nothing.
- [ ] 2c. Invoke the status enumeration as `git status --porcelain=v1 -z -uall --no-renames`. Assert all three flags in a test: `-uall` for the untracked-directory collapse, `-z` because porcelain v1 shell-quotes awkward paths, `--no-renames` so a rename decomposes into an absent record plus a present record.
- [ ] 2d. A path that exists but whose bytes, mode or link target cannot be read is UNCOMPUTABLE, not absent. Encoding it as absent would make a permissions failure indistinguishable from a deletion. Comment this at the call site.
- [ ] 3. Keep a path-level `git status --porcelain=v1 -z -uall --no-renames` digest as one corroborating signal only. Wherever it appears, `-uall` is mandatory; assert it in a test. Same invocation as the content digest's status enumeration — there is one status call per root per snapshot, not two.
- [ ] 4. Write both verified blind spots into the header of `lib/evidence.sh` and into the spec: (a) without `-uall` an untracked directory collapses to one `?? dir/` line, so files 2..N inside it produce a byte-identical digest; (b) with or without `-uall` the digest is blind to content changes within a path whose status string does not change. Cite the 2026-07-28 `bugeventlog.md` root-cause entry.
- [ ] 5. Fail closed on evidence-computation failure: non-git WORK root, non-zero digest command, unreadable declared deliverable. Record `INCONCLUSIVE` with a distinct reason; never interpret the failure as "no change". The git-work-tree condition applies to the work root ONLY — an artifact root that is not a git work tree (the run directory) is computable by content records over the declared deliverables and is NOT a computation failure. Assert both halves; the old code path that rejected any non-git root is the known-bad input.

## T2 — declared deliverable sets and lane-type contracts

- [ ] 6. Resolve and persist a declared deliverable set for every round before the vendor is invoked. Each entry carries a path AND a required end state (`present` or `absent`). Refuse dispatch when the set is unresolvable: empty, an entry under neither declared root, an entry missing its end state, or no assignment artifact and no lane-type default. Record the ground of unresolvability in the configuration error.
- [ ] 6a. Make the set unforgeable. It is resolved by the orchestrator from lane type + lane assignment; it is NEVER read from the lane's output stream, from a manifest the lane writes, or from any file the lane process can write. At post-round evaluation, compare the set in hand byte-for-byte against the set recorded before dispatch; a mismatch is a configuration failure that blocks the gate and is NOT evaluated under either set. Test with a lane that writes its own deliverable manifest naming a file it did produce — it must still fail.
- [ ] 6b. Never dispatch into an already-satisfied contract. Order matters: perform any lane-type pre-dispatch invalidation FIRST (for `audit`, publish the in-progress verdict), THEN evaluate the lane-type final-state conditions and record the result plus the pre-round digest as the round's PRE-DISPATCH BASELINE. Taking the baseline before invalidation would make every legitimate re-audit look like a stale artifact. If they already hold: end the loop (lane satisfied) when the run record attributes the artifacts to a completed round of this same lane; otherwise refuse dispatch with a stale-artifact configuration error naming each pre-existing artifact. Do not dispatch a round a do-nothing lane would pass. Scope this to ONE lane assignment's evidence loop: a rework round responding to audit findings is a new lane instance with its own declared set and must still dispatch; attempt-fresh production (7b), not this rule, is what stops it being credited for nothing. Test both directions — the rework round dispatches, and a rework round that writes nothing fails.
- [ ] 7. Define the four lane-type evidence contracts, each naming FIVE things: work root, artifact root, required artifacts, validation command and report location: implement, audit, planning, research.
- [ ] 7a. Implement the two-root split. Work root: the worktree the lane operates on or reviews; MUST be a git work tree; digest covers declared deliverables under it plus the status enumeration. Artifact root: where required artifacts are written; NOT required to be a git work tree; digest covers exactly the declared deliverables under it, no status enumeration. Same directory permitted for implement/planning/research; for `audit` they MUST differ and the artifact root MUST NOT lie inside the work root. Record both roots and stamp every evidence result with the root it was computed over.
- [ ] 7b. Implement attempt-fresh production as part of EVERY lane-type artifact assertion: at least one declared deliverable's canonical record must differ between that round's own pre-dispatch baseline and its post-round digest. Compare against the round's own baseline, never an earlier round's, or a resumed lane inherits its predecessor's credit.
- [ ] 8. Implement lane type `implement`: work root = artifact root = the lane worktree; success requires attempt-fresh production on a declared deliverable, every declared deliverable at its required end state, and a zero-exit validation command; an incidental touch outside the deliverable set is not success. An unchanged implement round under a trusted mechanism is a FAILURE, not an exempt observation — no `INCONCLUSIVE` path may reach it.
- [ ] 9. Implement lane type `audit`: work root = the reviewed worktree; artifact root = a directory outside it, defaulting to `$FOREMAN_HOME/runs/<run-id>/reports/` (orchestrator-owned, not a git work tree, and that is legal under 7a). Success requires a verdict artifact that exists, is schema-valid, carries the attempt id allocated before spawn, carries `state = "complete"`, and differs from its pre-dispatch baseline. Before spawning the auditor, replace whatever stands at that location with `three-outcome-verdicts`' in-progress record, so a pre-existing `APPROVED` cannot be inherited. An unchanged reviewed worktree is NOT a failure. Tampering = a changed canonical record on any work-root path that is NOT an entry of the recorded declared deliverable set; detected by content digest, never by a porcelain status string.
- [ ] 10. Implement lane types `planning` and `research`: every entry at its required end state (`present` = exists and non-empty; `absent` = does not exist), attempt-fresh production satisfied, and the validation command exits zero (`openspec validate <change> --strict` for OpenSpec packages). A skeleton SHALL NOT satisfy the contract; one changed file out of several SHALL NOT end the loop; and artifacts that predate the round SHALL NOT carry it.
- [ ] 11. Record termination metadata on every attempt, not only on unchanged-evidence failures.

## T3 — inconclusive semantics and the bounded loop

- [ ] 12. Implement `INCONCLUSIVE` as a property of the MECHANISM, not of the round, and make the two cases mutually exclusive in code so no round can fall under both. If the mechanism failed any planted-write control for the run, or the comparison could not be computed: record `INCONCLUSIVE` naming the ground, and let it contribute NOTHING to the round outcome in either direction. If the mechanism passed every control and the comparison was computed: an unchanged comparison is a trusted observation that the attempt produced nothing — do NOT label it `INCONCLUSIVE`, and decide the round from the lane-type artifact assertion (which requires attempt-fresh production for every lane type). Any resulting failure names the failed artifact assertion, with the unchanged comparison as corroboration only.
- [ ] 12a. Delete every code path that can report a terminal empty-burst failure from an unchanged digest ALONE, i.e. without an accompanying failed artifact assertion.
- [ ] 12b. Regression test the contradiction this closes: implement lane, attempt 1 writes every declared deliverable and the suite goes green; attempt 2 writes nothing. Attempt 2 must be recorded UNSUCCESSFUL. Assert it is NOT recorded `INCONCLUSIVE` and NOT recorded successful. This is the input the pre-fix text accepted, because "unchanged evidence is never terminal" and "an implement round that changes nothing SHALL NOT be successful" both applied to it.
- [ ] 12c. Regression test the case the fix must NOT break: the 2026-07-28 planning lane. A mechanism that fails a planted-write control reports no change for a round that wrote four complete valid files — the comparison is `INCONCLUSIVE` naming the failed control and NO terminal failure is emitted. Under the trusted content digest the same round reports a CHANGE and passes.
- [ ] 13. Wire pre-round and post-round evidence capture into lane-run.sh / lane-supervise.sh (or equivalent) for every lane type.
- [ ] 14. Implement the success predicate: exit code and agent self-report are never sufficient; the lane-type artifact assertion is required in every case.
- [ ] 15. Capture and persist vendor termination/stop reason (stopReason, cancellationCategory, or adapter-best-effort equivalent) alongside each round's evidence result, including an unknown/unavailable bucket.
- [ ] 16. Label unchanged-evidence failures with recorded termination metadata so empty-burst vs cancelled-writes remain distinguishable after the fact.
- [ ] 17. Implement `vendor-multiround.sh` here (owned by this package), invoking vendors only through vendor-adapter-contract's `adapter_implement_argv`; preserve the round>1 preamble and the feed-forward of the prior round's captured output.
- [ ] 18. Implement explicit loud terminal failure when the round budget is exhausted without the lane-type contract being satisfied: visible run status, report fields, downstream gate block.
- [ ] 19. Apply the evidence loop to non-grok vendors (codex, claude, agy, others) and non-implement lane types with the same budget and terminal-failure semantics.

## T4 — the planted-write positive control

- [ ] 20. Implement a planted-write positive control that runs at mechanism initialisation and in the release suite: plant a known write inside the lane's work root, confirm detection, revert.
- [ ] 21. Control corpus SHALL include the three verified blind cases — second file added inside an untracked directory, content rewrite of an existing untracked file, second edit of an already-modified tracked file — plus a planted DELETION of an existing tracked file (must report a change under the absent-state encoding) plus a negative control that writes nothing.
- [ ] 21a. Only a mechanism that passed every control for the run may produce the unchanged comparison that decides a round. Wire the trust flag into the decision in T3.12 rather than logging it; an untrusted mechanism's comparison must be structurally incapable of failing a round.
- [ ] 22. On any control failure, mark the mechanism unavailable with a reason naming the failed control and fail closed. No empty-burst verdict may be emitted by an untrusted mechanism.
- [ ] 23. Regression test: run the control corpus against the *old* predicate (`git status --porcelain | sha256sum`) and assert it FAILS at least the untracked-directory and untracked-rewrite cases. A control that the old predicate also passes does not demonstrate the fix.
